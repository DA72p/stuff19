# Close Enough is Nowhere Near — code and results

Code for the experiments in *Close Enough is Nowhere Near: Fidelity-Consumability
Decoupling in KV Caches*.

A frozen transformer reads a KV cache correctly only if that cache lies inside a
narrow neighbourhood of the one its own forward pass would have produced. The
experiments here measure that neighbourhood, show that fidelity metrics do not
predict membership in it, locate the cause at the softmax readout, and show that
augmentation (keeping the reader's cache and attending over the sender's as
additional context) is not bound the same way.

## Layout

```
notebooks/      one notebook per experiment, in paper order
results/        the result JSONs the paper reports (committed)
figures/        figures 1-4 as they appear in the paper
make_figs.py    regenerates figures 2-4 from results/
verify_results.py   re-checks the paper's numbers against results/ (no GPU)
```

## Reproducing the reported numbers without a GPU

Every number in the paper is committed under `results/`. To check the paper
against them:

```bash
pip install -r requirements.txt
python verify_results.py     # 20/20 reported values, exits non-zero on mismatch
python make_figs.py          # rewrites figures/fig{2,3,4}.png from results/
```

`make_figs.py` reproduces the paper's figures byte-for-byte from the committed
JSONs.

## Re-running an experiment

Each notebook is self-contained: it loads a frozen model, builds the probe, runs
its arms, and writes `results/<name>.json`. Nothing is shared between notebooks
and they can be run in any order. Open one in Jupyter, or run it headlessly:

```bash
./run_experiment.sh similar              # full run, the configuration the paper reports
KVL_FAST=1 ./run_experiment.sh similar   # smoke run at reduced eval size
```

`KVL_FAST=1` shrinks the eval set and the training schedule; use it to confirm a
notebook runs end to end before committing a GPU to the full version. Smoke
numbers are not paper numbers -- they carry their own anchors at small n.

| Notebook | Paper | What it measures |
|---|---|---|
| `similar.ipynb` | §3.1 | Calibrated noise vs. a genuine fact-bearing cache at matched cosine. The 89x inversion. |
| `depth.ipynb` | §3.2 | Corrupting the first *l* of 28 layers, with an on-manifold arm at matched cosine as the control that rules depth out. Also the 7-model L=6..36 check. |
| `oracle.ipynb` | §3.3 | Selection from a bank of 6000 genuine keys, swept over rank *k* and mixing weight. |
| `kappa.ipynb` | §4.1 | Readout conditioning at both stages: the off-/on-manifold gain ratio, and whether anything is amplified. |
| `grid.ipynb` | §5.1 | Nine cells: three codebook constructions x three snapping rules. |
| `xkvlora.ipynb` | §5.2 | Augmentation. Verbatim cross-attention with zero trained parameters, then the query-side LoRA ladder. Includes the cross-family arm. |
| `multixkv.ipynb` | §5.3 | Scaling the sender pool to N=8 with one answer-holder and N-1 distractors. |
| `partial.ipynb` | App. G | Sparse, feature-level damage and the key-vs-value split. |

The probe is split-context SQuAD: a holder reads the passage containing the
answer, the reader gets the same passage with the answer span masked. Transfer is
the fraction of items the reader answers correctly. Two anchors are re-measured
in every run rather than assumed:

- **floor** — the reader on its own masked cache, 0.180 at n=200
- **native-cache reference** — the same reader on its own *unmasked* cache, 0.665

The reference is a reference, not a proven upper bound. Runs at n=120 have their
own anchors (0.20 / 0.742) and are never compared against the n=200 figures.

## Requirements

One GPU. The reader is Qwen2.5-1.5B in fp32, so roughly 8 GB for the
substitution experiments; `multixkv.ipynb` holds several senders' caches at once
and wants more. Models and data come from HuggingFace on first run; set `HF_HOME`
to control where they land.
